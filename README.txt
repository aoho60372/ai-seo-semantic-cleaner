# AI SEO Semantic Cleaner

Workflow для чистки, классификации и кластеризации семантических ядер. Он работает через Hermes: модель принимает смысловые решения, а локальные Python-инструменты быстро обрабатывают данные и формируют итоговые таблицы.

## Быстрый запуск

1. Поместите исходный CSV, TSV или XLSX в папку `files`.
2. В Hermes отправьте `/sclear <имя_файла> <тематика>`.

   Пример: `/sclear semantic.xlsx Продажа автомобильных запчастей`

3. Дождитесь окончания. Результат будет в `outputs/<job>/semantic_clustered_review.xlsx`.
4. Откройте лист `Human review`, при необходимости исправьте значения в `Correct Intent`.
5. Сохраните файл под новым именем и отправьте в Hermes: `/sknow <имя_проверенного_файла>`.

   Пример: `/sknow semantic_clustered_reviewed.xlsx`

`/sknow` импортирует ручные исправления и сохраняет знания темы. Повторную чистку или кластеризацию он не запускает.

## Установка именно этого проекта

Нужны Windows, Git и Python 3.11+.

В PowerShell перейдите в папку, где хотите хранить проект, и выполните:

    git clone https://github.com/aoho60372/ai-seo-semantic-cleaner.git
    cd ai-seo-semantic-cleaner
    py -m venv .venv
    .\.venv\Scripts\python.exe -m pip install --upgrade pip
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt

### NVIDIA CUDA

Если есть NVIDIA GPU, которую можно использовать для embeddings, дополнительно установите CUDA-сборку PyTorch:

    .\.venv\Scripts\python.exe -m pip install -r requirements-cuda.txt
    .\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"

В выводе должны быть `True` и название видеокарты. Если CUDA недоступна, workflow автоматически продолжит работу на CPU.

### Локальная embedding-модель

Нужна локальная копия `multilingual-e5-small` в папке `../models/multilingual-e5-small` относительно корня проекта. Внутри должны быть как минимум `config.json`, `modules.json`, `model.safetensors` и `tokenizer.json`.

Во время работы загрузка с Hugging Face запрещена: модель берётся только из этой локальной папки. Это устраняет зависимость от сети и случайных обновлений модели.

### Hermes

Один раз установите пользовательские skills из `hermes_customizations/skills/sclear` и `hermes_customizations/skills/sknow`, затем перезапустите Hermes. Конкретная папка skills зависит от установленной версии Hermes; правила команд находятся внутри этих папок.

## Результаты

Основная книга `semantic_clustered_review.xlsx` содержит:

- `Commercial clusters` — коммерческие запросы, кластеры и уверенность;
- `Informational clusters` — информационные запросы, кластеры и уверенность;
- `Garbage` — нерелевантные и мусорные фразы;
- `Human review` — ограниченная очередь спорных запросов;
- `Cluster review`, `Quality report`, `Validation metrics`, `Run configuration` — сводка и технические данные.

Для ядер очень большого размера рядом могут появиться полные `.csv.gz`, `manifest.json` и дополнительные листы Excel. Excel нужен для проверки и сводки; CSV содержит полный массив, который может быть слишком большим для удобной одной книги.

## Как работает workflow

### 1. Подготовка данных

`/sclear` передаёт имя файла и тему контроллеру `seo_workflow.py`. Он проверяет входные данные, создаёт папку `jobs/<job>/`, конфигурацию, журнал и `state.json`.

Подготовка читает XLSX, CSV или TSV в подходящей кодировке: UTF-8, UTF-8 BOM, CP1251 либо CP866. Колонка фраз определяется автоматически: поддерживаются `Поисковый запрос`, `query`, `keyword`, `фраза`, `запрос` без учёта регистра. Пустые строки исключаются, технические дубликаты объединяются.

`state.json` хранит этап, тему, количество меток и путь к последнему результату. Поэтому Hermes может продолжить задачу после сжатия контекста или новой сессии, не перечитывая историю чата.

### 2. Роль модели

Скрипты не заменяют модель. Hermes и выбранная основная модель понимают предметную область и размечают короткие пакеты запросов как `commercial`, `informational` или `garbage`.

Сначала выбирается около 100–150 разнообразных фраз. Затем Python выбирает следующие 50–100 наиболее неуверенных и противоречивых строк. Это active learning: модель тратит токены на действительно сложные решения, а не на сотни тысяч очевидных фраз.

Обычно достаточно примерно 200 меток. Для очень грязного ядра допускается около 400, чтобы точнее отделить мусор. Система не требует искусственно создавать класс `garbage`, если реального мусора в данных нет.

### 3. Классификатор и знания

На метках модели и ранее подтверждённых вручную примерах обучается лёгкий классификатор `scikit-learn` — Logistic Regression. Он переносит решение на похожие фразы, используя смысловые векторы, а не простые словари маркеров.

`seo_knowledge.py` хранит ручные исправления в локальной SQLite-базе. Это не дообучение нейросети и не обучение облачной LLM. Знания прошлой темы помогают следующей задаче, но являются только подсказкой: новая выборка и разметка всегда важнее.

### 4. Embedding-модель

`multilingual-e5-small` — отдельная нейросеть, превращающая фразу в вектор чисел. Близкие по смыслу запросы получают близкие векторы. Она не генерирует текст и не решает SEO-задачу сама.

`seo_embeddings.py` загружает только локальную E5, автоматически выбирает CUDA при доступной NVIDIA GPU либо CPU, кодирует фразы пакетами, добавляет префикс `query: ` и нормализует векторы. Основная LLM лучше решает неоднозначные смысловые вопросы, но слишком медленна и дорога для векторизации сотен тысяч строк; E5 предназначена именно для массовой локальной операции.

### 5. Обычный режим: до 100 000 фраз

1. Для уникальных фраз рассчитываются embeddings.
2. Классификатор назначает интент и уверенность.
3. Коммерческие и информационные запросы группируются через UMAP и HDBSCAN.
4. TF-IDF предлагает названия кластеров.
5. Создаётся Excel-результат и очередь `Human review`.

Это наиболее детальный вариант кластеризации, но глобальные UMAP/HDBSCAN не подходят для миллионов строк.

### 6. Крупный режим: более 100 000 фраз

Режим выбирается автоматически. Если большой файл — XLSX, workflow во временной папке преобразует только нужные колонки в TSV и удаляет его после работы. Затем данные читаются частями, обычно по 50 000 строк.

Для каждой части строятся embeddings и классификация, результат сохраняется как сжатый CSV. Embeddings временно кэшируются на диске: во втором проходе кластеризации они считываются из кэша, а не рассчитываются повторно. По репрезентативной выборке `MiniBatchKMeans` создаёт центроиды; остальные фразы получают ближайший кластер. Неуверенные строки попадают в `Human review`.

После успешного создания `manifest.json` и Excel кэш embeddings автоматически удаляется. При ошибке он сохраняется для диагностики.

## Компоненты проекта

| Файл или папка | Назначение |
|---|---|
| `seo.ps1` | UTF-8-обёртка для команд Python из PowerShell. |
| `seo_workflow.py` | Контроллер: этапы, состояние, блокировки, компактный JSON-статус. |
| `seo_prepare.py` | Чтение входного файла, поиск колонки, подготовка выборок и конфигурации. |
| `seo_pipeline.py` | Классификация, кластеризация и экспорт результатов. |
| `seo_embeddings.py` | Офлайн-загрузка E5, CUDA/CPU и пакетное кодирование. |
| `seo_knowledge.py` | Импорт ручных исправлений в SQLite-базу знаний. |
| `jobs/<job>/` | Временное рабочее состояние и журналы конкретной задачи. |
| `outputs/<job>/` | Готовые книги, части CSV и манифесты. |

## Автономность и диагностика

- Долгие запуски выполняются в фоне; модель получает короткий статус вместо длинных логов.
- Полный журнал задачи находится в `jobs/<job>/logs/run.log` или `run_large.log`.
- Блокировка не даёт одновременно дважды запустить одну и ту же job.
- После успешного импорта знаний папку `jobs/<job>` можно оставить для аудита либо удалить. Результаты в `outputs` и база знаний не исчезнут.

Обычно достаточно `/sclear` и `/sknow`. Для диагностики доступны команды:

    .\seo.ps1 status --job "<job>" --compact
    .\seo.ps1 sample --job "<job>" --offset 0 --limit 50
    .\seo.ps1 next --job "<job>" --quiet

Сначала проверяйте `state.json` и журнал. Не выводите целый XLSX или CSV в чат: это не помогает обработке и быстро расходует контекст модели.

## Ограничения

- Workflow не проверяет живую поисковую выдачу, частотность или ценность фраз через внешние SEO-сервисы.
- Качество зависит от темы, стартовой разметки и проверки пограничных случаев человеком.
- Кластеры — смысловая группировка, а не готовая структура сайта без редакторской оценки.
- Если локальная основная LLM занимает тот же GPU, можно задать в конфигурации `embedding_device: "cpu"`, чтобы не конкурировать за VRAM. С облачной основной моделью CUDA для embeddings обычно быстрее.
- Не заменяйте локальную embedding-модель именем из Hugging Face в конфигурации: это нарушит офлайн- и воспроизводимый режим.
